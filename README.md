# Next up

Next up offers Farm and Practice sections for osu!standard on lazer, using clean passes, recent failures and difficulty calculated with the selected mods. Practice offers manageable challenges and normal-speed trials when supported by evidence. Farm uses community top-score prevalence from osu!pps, adjusted for popularity and map age, along with pp efficiency and short repeatable attempts. Personal pp gain remains part of the ranking, but is not the definition of a farm map. Unranked adjustments and unfamiliar mod trials are excluded from Farm; estimates omit bonus pp and may differ from live osu! values. Both sections select up to 60 distinct maps from a bundled, precomputed catalogue. Map/mod difficulty and lazer FC pp curves are calculated before deployment, so recommendations do not download or recalculate candidate maps. The first profile sync reads two score endpoints and may calibrate up to three reference maps for an unfamiliar profile; subsequent recalculations reuse the session snapshot for a minute. Weighted gain uses the latest top 100 scores and is approximate. Reading and difficulty limits take precedence over filling the list.

Players can enter their osu! ID and sign in through osu!'s authorization page. Each session has its own recommendations and feedback, and passwords are entered only on osu!'s website. The application requests the `public` and `identify` permissions, which provide the signed-in profile and public gameplay data.

Run the Python service with the included Render configuration or another Python host. Set `APP_URL` to the service's HTTPS address and register `/auth/callback` at that address as the osu! application's callback. Store `OSU_CLIENT_ID`, `OSU_CLIENT_SECRET` and `SESSION_SECRET` as host environment secrets, and use one server worker because session state is held in memory. The public files contain no player profile or saved recommendation list.

Tokens and calculated lists remain in server memory and expire after six hours without activity. Signing out removes the session, and server restarts require players to sign in again. Non-credential difficulty preferences and feedback are stored in the player's browser by account. Cached beatmap files contain public map data and can be discarded.

A free Render service sleeps when unused, so its first visit may take about a minute. The source can move to another Python host, while saved browser preferences remain available on the same website origin. No hosting service promises permanent availability.

Beatmap buttons open `osu://b/<ID>`. Players still need to apply the displayed mods in lazer. The suggestions use aggregate map attributes, so replay-level pattern diagnosis remains outside the current algorithm.

The public farm metadata is derived from [grumd/osu-pps](https://github.com/grumd/osu-pps), with its MIT license included in `CATALOG-LICENSE.txt`. The top-score prevalence measure is evidence of farm popularity rather than proof that every map is objectively overweighted. The catalogue contains only public map metadata, difficulty features and pp curves, with no player profiles or score records.
